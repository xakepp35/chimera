# Chimera — сеть, которую нельзя заблокировать точечно

Проблема современных VPN в том, что у них почти всегда есть **стабильный признак**, за который можно зацепиться: IP сервера, характерный handshake, TLS/QUIC fingerprint, порт, формат пакетов или статистический профиль трафика.

Поэтому предлагается создать **Chimera — минимальное защищённое сетевое ядро**, в котором принципиально разделены:

```text
IDENTITY ≠ IP ≠ ROUTE ≠ TRANSPORT
```

Узел Chimera имеет постоянную **криптографическую identity**, но не обязан иметь постоянный IP, маршрут или протокол передачи.

Один логический Link может работать поверх разных carrier'ов:

```text
                Chimera Link
                     │
       ┌─────────────┼─────────────┐
       ▼             ▼             ▼
     QUIC         HTTP/3        MASQUE
       │             │             │
       └─────────────┼─────────────┘
                     ▼
                  Internet
```

Причём Chimera не должна **маскировать свой протокол под HTTPS**. Она должна реально использовать корректные массовые протоколы — HTTP/3, QUIC, MASQUE, WebTransport и последующие стандартные transport'ы.

Это даёт несколько фундаментальных свойств.

### 1. Нечего заблокировать по сигнатуре

У Chimera нет обязательного собственного wire protocol.

Сегодня Link работает через HTTP/3, завтра через MASQUE, затем через другой carrier. Overlay-сеть выше при этом не меняется.

---

### 2. Нечего заблокировать по одному IP

Identity узла не равна его адресу.

```text
NodeId
   │
   ├── endpoint A
   ├── endpoint B
   ├── endpoint C
   └── relay route D
```

Endpoint исчез — identity остаётся доступной другим путём.

---

### 3. Блокировка carrier не ломает сеть

Carrier — сменный механизм доставки, а не фундамент протокола.

```text
HTTP/3   BLOCKED
MASQUE   PASS
QUIC     PASS
```

Chimera выбирает доступный путь и продолжает работу.

---

### 4. Трафик смешивается с обычным Интернетом

Вместо отдельного «VPN-трафика» Chimera использует те же протоколы и инфраструктуру, которыми пользуются обычные приложения.

Следовательно, DPI приходится выбирать между:

```text
ALLOW legitimate traffic + Chimera
```

и

```text
BLOCK Chimera + часть legitimate traffic
```

Чем больше anonymity set и shared infrastructure, тем дороже точечная блокировка.

---

### 5. Маршрут тоже не является постоянным

Chimera может строить:

```text
Client → Gateway
```

или:

```text
Client → Relay → Relay → Exit
```

или:

```text
Client → Overlay Service
```

Поэтому блокировка конкретного relay или gateway не уничтожает логическую сеть.

---

## Основная идея

Мы не пытаемся построить:

> **VPN, который DPI сложнее распознать.**

Мы строим архитектуру, в которой **нет одного стабильного объекта, который можно распознать и отключить**.

```text
identity      меняется независимо от location
location      меняется независимо от route
route         меняется независимо от carrier
carrier       меняется независимо от overlay
```

Поэтому селективная блокировка постепенно сводится к задаче:

```text
Block(Chimera)
        ↓
distinguish Chimera from legitimate traffic
        ↓
нет устойчивого protocol/IP/route fingerprint
        ↓
приходится блокировать общий carrier или инфраструктуру
        ↓
collateral damage
```

Целевой инвариант Chimera:

```text
Cost(selectively_block_chimera)
        >>
Cost(block_normal_vpn)
```

В пределе:

```text
Block(Chimera)
    ⇒
Block(significant legitimate Internet traffic)
```

Абсолютно неблокируемых сетей не существует: можно отключить весь Интернет.

Но Chimera должна сделать **точечную блокировку настолько дорогой и разрушительной для обычного трафика, чтобы цензор потерял главное преимущество DPI — возможность дешёво отличить VPN от остального Интернета.**

Именно поэтому Chimera — не ещё один VPN-протокол.

Это **минимальное сетевое ядро, у которого идентичность, маршрут и физический транспорт принципиально не связаны между собой**.
